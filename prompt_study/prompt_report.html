Smell-inducing prompts

What happens when models are asked for code that is structurally demanding by design, rather than for the short self-contained functions the correctness benchmarks use.

476 Python prompts, each written to provoke a named structural defect, from the Code Smell Detection Dataset (2026), used with permission and cited in the write-up. Two models, each run twice under different instructions.

Why this exists

The main evaluation uses MBPP and HumanEval, where a task is a single short function. That is a real limitation: most of the twelve defects cannot physically occur in a five-line answer, so only four or five ever appeared and the evaluation was under-powered for exactly the problems it was built to study.

These prompts ask for something different — a function that validates input, calculates totals, applies discounts, updates inventory, generates an invoice, sends a confirmation and logs the transaction. Work of that shape has room for a long method, deep nesting, or duplicated blocks. The question this page answers is whether that room gets used.

What can and cannot be measured here

These prompts come with no tests and no reference solutions. So correctness cannot be measured — there is nothing to execute against — and neither can any similarity measure, since those compare code to a known-good version. What runs is the reference-free half of the panel: the detectors, and the structural measures. That is the same half the detection report validated on real code, so it is the half we have grounds to trust here.

Completeness: was the work actually done?

A structural measure cannot tell a well-decomposed solution from a skeleton of empty functions — both look short and simple. Code that was never written cannot carry a defect, so a model can score well by not doing the work. Every structural number on this page is therefore reported next to how complete the code is.

Did the prompt induce the defect it targeted?

Each prompt names the defect it was written to provoke, which makes this a labelled test rather than a profile: for each one we can ask whether the thing the prompt was engineering for actually appeared.

The prompt set uses Fowler's 25-category catalogue; this project tracks the twelve a static analyser can confirm. Six overlap, so induction is measurable on 152 of the 476 prompts. The other 324 still contribute everything else on this page — the detectors fire on whatever they find, regardless of what the prompt was aiming at.

How to read this, and what it does not show

  • No correctness anywhere on this page. These prompts have no tests. A generation counted as clean here may not work at all; structural quality and correctness are independent properties and only one of them is measured.
  • Induction is measured on 152 prompts, not 476. Only six of the prompt set's categories overlap with the twelve this project can confirm.
  • Detectors define the defects. They are an operational definition, not ground truth, and the structural measures are evaluated against them rather than the other way round.
  • Two small instruct-tuned models. Findings here describe these models at this scale, not language models in general.

# Dependencies for the hosted dashboard (Render / Hugging Face Space / any container).
# Deliberately excludes torch, transformers and datasets -- those belong to the GPU
# generation phase and would make the image enormous.
#
# VERSIONS ARE PINNED ON PURPOSE. Unpinned, every redeploy resolves to whatever was
# released that day, so a build that worked last week can fail today with no change
# on our side and no way to reproduce it. These are the versions verified to install
# and start the dashboard cleanly. Move them deliberately, rather than discovering a
# change through a failed deploy.
# Every pin here must exist for the PYTHON_VERSION set in render.yaml (3.11.9).
# numpy is the cautionary case: it is not a direct dependency at all -- it arrives
# through sacrebleu -- and pinning it to a version resolved on a newer Python made
# the build unsatisfiable, because numpy 2.5 requires Python 3.12 or later. It is
# now bounded rather than fixed, which constrains it without tying it to an
# interpreter it cannot run on.
flask==3.1.3
numpy<2.5
radon==6.0.1
pylint==4.0.6
ruff==0.16.1
cognitive_complexity==1.3.0
sacrebleu==2.6.0
rouge-score==0.1.2
# nltk arrives through rouge-score and is pinned here because it is the dependency
# that actually broke the deploy: 3.10 added a guard that blocks importing a module
# resolved from the working directory, which is where Render puts the virtualenv.
# PYTHONSAFEPATH=1 in render.yaml satisfies the guard; this pin means the version
# cannot change again without us choosing it.
nltk==3.10.1
tree-sitter==0.26.0
tree-sitter-python==0.25.0

# codebleu is installed separately with --no-deps (it pins an old tree-sitter that
# would otherwise downgrade the two above). Its import is guarded in measures.py, so
# the dashboard still runs without it.
#
# zss was removed: AST similarity now uses difflib over the node-type sequence, which
# is far faster and needs no extra dependency.
#
# nltk and the WordNet corpus went with METEOR. Nothing in the panel needs them.
